# Enemy-memory expected results

This fixture supplies expected results for
`tools/recomp/test_faction_enemy_memory_native.py`. The test requires the supported
retail XBE, generated recompilation, Python and MinGW GCC.

## Provenance

The current expected results are generated by executing the supported retail
XBE instructions under the publicly available Unicorn x86 emulator. The generator
does not read an older expectation fixture. Its input hash,
function addresses, ABI/layout evidence, tool version and output hashes are in
`manifest.json`. The source of the generator is bundled as
`tools/recomp/capture_enemy_memory_retail.py`.

On 2026-09-29 the full 20,772,212-byte trace was independently reproduced
from retail execution, byte for byte. This establishes a retail-only way to
reproduce these results.

To regenerate, install the manifest's public Unicorn version and run:

```powershell
python tools/recomp/capture_enemy_memory_retail.py game_files/mercenaries-retail/default.xbe artifacts/retail-enemy-memory
```

Review and compare the output before replacing the bundled fixture. Ordinary
regression runs need no Unicorn installation or private input.

## Coverage

The existing scenarios are preserved: 100,000 deterministic randomized operations
(seed `0x13572468`), 30/60/120 Hz timeout expiry, refresh and eviction, four-slot
state comparisons, all twelve queried IDs after each comparison, and 2,049
personal-relation input values tested across remembered, unknown and expired
states. Relationship expectations still use the pre-existing retail-constant
formula in the test; the fixture records the EnemyList oracle results.
The harness continues checking guest stack and nonvolatile-register preservation.
This finite sequence does not establish correctness for every possible input.

## Format and validation

`expected.bin.gz` is deterministic gzip containing `ENMEM001`, then little-endian
32-bit record words. Floats are stored as IEEE-754 binary32 bits. Each record
starts with an opcode, followed by these words:

| Opcode | Payload |
|---|---|
| 1: init | none |
| 2: update | elapsed-time input |
| 3: find | ID input, float result |
| 4: add | ID input, timeout input, unsigned result |
| 5: remove | ID input, unsigned result |
| 6: state | base time, then four ID/timeout pairs |

Unused-slot timeout words are canonicalized to zero; the original comparison
ignored them. `replay.c` is a protocol reader, not an implementation of enemy
memory. It verifies every operation and input before returning recorded results,
and rejects missing or extra records. Python verifies the compressed and raw
hashes and the supported retail XBE hash before compiling the harness.

Changing the operation sequence requires a separately documented replacement
fixture. Do not regenerate expectations from the implementation under test and
call that independent validation. The bundled generator supplies a retail/emulator reference independently of the
recompiled implementation under test.
